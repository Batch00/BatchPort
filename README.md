# BatchPort

Personal travel tracker and installable PWA. See where you have been and plan
where you are going.

This repository currently contains the foundational app shell only. The map and
travel features come later.

## Stack

- Next.js (App Router) with TypeScript in strict mode
- Tailwind CSS v4 and shadcn/ui (dark, minimal theme)
- Supabase via `@supabase/ssr` (current server-side auth pattern)
- Deploys to Vercel
- Installable PWA baseline (manifest, icons, pass-through service worker)

## Prerequisites

- Node.js 20 or newer (built and tested on Node 22)
- npm
- A Supabase project (shared across several apps, each in its own Postgres
  schema). BatchPort uses the `batchport` schema.

## Setup

1. Install dependencies:

   ```bash
   npm install
   ```

2. Create your local environment file from the template and fill in real values:

   ```bash
   cp .env.local.example .env.local
   ```

   `.env.local` is gitignored. Never commit real secrets. The committed
   `.env.local.example` documents every variable, including which ones are
   server only.

3. In the Supabase dashboard, make sure the `batchport` schema is added under
   Settings, API, Exposed schemas. All Supabase clients in this app are pinned
   to that schema, so it must be exposed to the API for data access to work.

## Environment variables

See `.env.local.example` for the full list. Summary:

| Variable | Scope | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | public | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | public | Supabase anon key |
| `NEXT_PUBLIC_APP_URL` | public | Canonical app URL for auth redirects and absolute links |
| `NEXT_PUBLIC_PMTILES_URL` | public | Base URL for the PMTiles basemap (used by the map later) |
| `SUPABASE_SERVICE_ROLE_KEY` | server only | Privileged server-side Supabase access |
| `RESEND_API_KEY` | server only | Transactional email |
| `BATCHPORT_ADMIN_EMAIL` | server only | Where access request notifications are sent |
| `APPROVAL_SECRET` | server only | Secret used to sign approval and deny tokens |
| `NOMINATIM_USER_AGENT` | server only | Contact string sent as the User-Agent to Nominatim geocoding |

Until the `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`
variables are set, the app shell still renders: the session refresh in
`src/proxy.ts` is skipped when they are absent.

## Scripts

```bash
npm run dev     # start the dev server at http://localhost:3000
npm run build   # production build (type checks the whole project)
npm run start   # serve the production build
npm run lint    # run ESLint
```

## PWA icons

Placeholder icons live in `public/icons` (192, 512, and a maskable 512). They
are generated by a small dependency-free script. Regenerate them with:

```bash
node scripts/generate-icons.mjs
```

Swap in real artwork by replacing the files in `public/icons`, keeping the same
names and sizes referenced in `src/app/manifest.ts`.

## Notes

- Brand accent: the electric blue brand color is the `--brand` CSS variable in
  `src/app/globals.css` (default `#2563EB`) and is exposed to Tailwind as the
  `brand` color, so utilities like `bg-brand` and `text-brand` work. Swap in the
  exact Batch Apps hex in one place.
- Theme: the app is dark only. The `dark` class is applied on `<html>` in the
  root layout.
- Proxy, not middleware: Next.js 16 renamed the `middleware` file convention to
  `proxy`. The per-request session refresh lives in `src/proxy.ts` (the former
  `src/middleware.ts`); behaviour is unchanged.
- Service worker: `public/sw.js` is a pass-through with no offline caching yet.
  It exists so the app is installable. Offline support is planned for a later
  version.

## Deploy

Deploys to Vercel. Set the same environment variables from `.env.local.example`
in the Vercel project settings before deploying.
